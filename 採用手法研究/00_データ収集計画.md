# 採用手法の教科書｜データ収集計画

最終更新: 2026-08-13 / ステータス: v1（骨格設計）

---

## 0. この計画の前提

### 0-1. 「日本一詳しい」を操作的に定義する

「詳しい」を定義しないまま情報を集めると、Web記事の要約が積み上がるだけで終わる。
収集の前に、到達点を検証可能な形にしておく。

**到達状態の定義：**

> 任意の企業条件（規模・業種・所在地・予算・採用職種・採用人数・時間制約）を提示されたとき、
> ①取りうる手法の全選択肢を漏れなく挙げ、②各手法の単価・歩留まり・リードタイムの相場を数字で答え、
> ③なぜその企業条件ではこの手法が効き、あの手法が効かないのかを機序で説明し、
> ④それを裏づける一次情報の出所を提示できる。

この4つのうち、世の中の情報が既に十分に供給しているのは①だけである。
②③④が差別化の実体であり、**データ収集計画の重心は②③④に置く**。

### 0-2. 差別化の源泉はどこにあるか

| 知識レイヤー | 市場での希少性 | 主な入手経路 |
|---|---|---|
| 手法の名前と概要 | ほぼゼロ（記事で無料） | Web・書籍 |
| 手法の仕組み（金と情報の流れ） | 低〜中 | ベンダー資料・商談 |
| 料金体系と交渉相場 | **高** | 商談・実務者証言 |
| 手法別の歩留まり実測値 | **極めて高** | 自身の関与案件・ATSデータ |
| 条件別の効き方（適合条件） | **極めて高** | 横断比較 + 反証事例 |
| 手法の歴史と生成理由 | 中〜高 | 一次資料・年表化作業 |
| 学術的な予測妥当性 | 中（英語圏に偏在） | 論文 |

→ 収集の時間配分は「高・極めて高」に7割を割く。低希少性レイヤーは**網羅性の担保だけが目的**で、
速く広く1回で終わらせる。

### 0-3. 設計原則

1. **スキーマ先行**：何を集めるかを決める前に、集めた結果が入る「箱」の型を決める。箱の型が教科書の章立てになる。
2. **セル充填として設計する**：収集を「読書」ではなく「マトリクスの空欄を埋める作業」として管理する。進捗が可視化され、抜け漏れが自動的に検出される。
3. **出典メタデータ必須**：「誰が・誰に・何を売るために・いつ・何社に聞いた数字か」を書けない情報は採用しない。
4. **反証を義務として集める**：各手法に「効かなかった事例」を最低3件。成功事例だけを集めると条件依存性が見えなくなる。
5. **アウトプットは収集手段**：書いて出すと、当事者から訂正と裏情報が飛んでくる。Phase 5 は執筆ではなく**収集フェーズ**として設計する。

## 1. 収集の骨格：5つの分類軸

手法を一次元のリストで並べると必ず破綻する。以下の5軸の直積で管理する。

### 軸A：採用ファネル上の機能

| 段階 | 機能 | 例 |
|---|---|---|
| A1 認知・興味 | 存在を知らせる | 採用広報、オウンドメディア、登壇、SNS |
| A2 母集団形成 | 応募・接点を作る | 求人広告、エージェント、スカウト、リファラル |
| A3 選抜 | 見極める | 面接、適性検査、ワークサンプル、リファレンス |
| A4 動機づけ・クロージング | 決めさせる | 面談設計、オファー面談、条件提示、体験入社 |
| A5 定着・立ち上がり | 辞めさせない | オンボーディング、受け入れ設計 |

※世間で「採用手法」と呼ばれるものは A2 に偏る。**A3〜A5 を同じ解像度で扱えることが差別化になる**。

### 軸B：チャネル分類（A2の内訳）

- **有料媒体**：掲載課金型求人広告 / 成果報酬型求人広告 / 求人検索エンジン（運用型）/ アグリゲーション
- **仲介**：人材紹介（登録型）/ サーチ型ヘッドハンティング / 再就職支援 / 紹介予定派遣 / RPO
- **ダイレクト**：スカウト媒体 / SNSダイレクト / 技術者コミュニティ経由（GitHub・Kaggle 等）/ タレントプール
- **関係資本**：リファラル / アルムナイ / 出戻り / 縁故 / 副業・業務委託からの転換
- **接触機会創出**：カジュアル面談 / ミートアップ / 勉強会 / インターンシップ / 学校・研究室ルート
- **公共・制度**：ハローワーク / 新卒応援ハローワーク / 各種助成金連動 / 特定技能・技能実習等の外国人採用スキーム
- **その他**：採用ピッチ資料、採用ブランディング、M&A的アクハイヤー

### 軸C：選抜手法分類（A3の内訳）

- 面接：非構造化 / 半構造化 / 構造化 / 行動面接（BEI）/ ケース面接 / 逆質問設計
- テスト：一般認知能力（GMA）/ パーソナリティ検査 / 適性検査各種 / 語学 / 技能テスト
- 実技：ワークサンプル / コーディングテスト / 課題提出 / 体験入社・トライアル
- 集団：グループディスカッション / グループワーク / アセスメントセンター
- 外部検証：リファレンスチェック / バックグラウンドチェック / SNS確認（法的論点あり）
- 新技術：AI面接 / 動画選考 / 自動スクリーニング（差別リスクの論点あり）

### 軸D：市場セグメント（**最重要**）

同じ手法でもセグメントが変われば別物になる。教科書の縦軸はここ。

新卒（総合職／技術職／体育会等）・中途（メンバー／管理職／エグゼクティブ／専門職）・
アルバイト／パート・派遣・業務委託／フリーランス・現業／ドライバー／介護／医療・
外国人・障がい者採用・シニア再雇用

### 軸E：発注企業側の条件

規模（〜30／〜300／〜1000／それ以上）・知名度・業種・所在地（都心／地方／複数拠点）・
採用人数（1名／数名／数十名／数百名）・給与水準の市場内位置・採用予算・人事体制の厚み・時間制約

> **教科書の核心成果物 = 軸D × 軸E × 軸B/C の適合マトリクス**
> データ収集とは、このマトリクスのセルを埋める作業に他ならない。

## 2. 手法カードのスキーマ

1手法 = 1カード。全手法で同じフィールドを埋める。フィールドが埋まらない箇所が「次に取りに行くデータ」になる。

```
【識別】
  手法名 / 別名・英語名 / 軸A分類 / 軸B・C分類 / 成熟度（黎明・成長・成熟・衰退）

【機序】
  一言定義
  金の流れ（誰が誰にいくら、どのタイミングで払うか）
  情報の流れ（候補者情報が誰から誰にどう渡るか）
  なぜ機能するのか（機序の言語化：情報の非対称性を何で埋めているか）

【歴史】
  登場時期 / 普及の契機（技術・法制度・労働市場の変化）
  先行手法との代替・補完関係 / 衰退している場合はその理由

【市場】
  主要プレイヤー（社名・サービス名）
  料金体系の型（掲載課金／成果報酬％／月額固定／従量）
  価格レンジ（表示価格 と 実勢価格 を分けて記録）
  交渉余地（何を条件に何%引けるか）

【効果】
  KPI相場：応募単価 / 書類通過率 / 面接通過率 / 内定承諾率 / 採用単価(CPH) / リードタイム / 1年定着率
  ※必ず「どのセグメント・企業条件での数字か」を併記。条件なしの数字は記録しない

【適合】
  効きやすい条件（軸D×軸Eで記述）
  効かない条件
  前提となる社内リソース（工数・人事体制・現場の協力）

【リスク】
  法的制約（該当法令・指針）
  実務上の落とし穴 / 失敗パターン
  ベンダー側のインセンティブ構造から生じる歪み

【エビデンス】
  学術研究の有無と結論
  反証事例（最低3件）
  自身の実測データへのリンク

【出典】
  各記述の出所・発行主体・利害関係・調査対象(n)・調査年
```

**初期の対象手法数：40〜60**（軸B・Cの列挙をそのままカード化）

## 3. データソース地図（5層）

### 層1：公的統計・法制度（信頼性◎／無料／土台）

| 対象 | 何が取れるか |
|---|---|
| 厚生労働省 労働経済動向調査 | 求人・採用の企業側動向、未充足求人 |
| 厚生労働省 雇用動向調査 | 入職経路別の構成比（**手法シェアの基礎データ**） |
| 職業安定業務統計 | 有効求人倍率（職種別・地域別） |
| 総務省 労働力調査 | 労働市場全体の需給 |
| リクルートワークス研究所 | 大卒求人倍率調査、中途採用実態調査、全国就業実態パネル調査 |
| JILPT（労働政策研究・研修機構） | 採用・雇用に関する調査研究、日本労働研究雑誌 |
| 内閣府・経団連 | 就活日程に関する要請、採用選考ルールの変遷 |

**法制度（手法の制約条件として必ず押さえる）：**
- 職業安定法（2022年改正：募集情報等提供事業の届出制、的確表示義務など）
- 労働施策総合推進法 第9条（募集・採用における年齢制限の原則禁止と例外事由）
- 男女雇用機会均等法（募集・採用における性別差別の禁止、間接差別）
- 個人情報保護法（リファレンス・バックグラウンドチェック・スカウトでの個人情報取扱い）
- 労働基準法15条・職安法5条の3（労働条件の明示、2024年4月の明示事項追加）
- インターンシップの取扱い（三省合意の2022年改正／採用活動での情報活用の可否）
- 障害者雇用促進法、外国人雇用関係（在留資格・特定技能・技能実習）

→ **成果物：法制度年表 + 「この手法にはこの規制がかかる」対応表**

### 層2：業界・ベンダー調査（速報性◎／バイアス要注意）

- 大手ベンダーの調査レポート（リクルート、パーソル、マイナビ、エン、ビズリーチ、Wantedly 等）
- 求人掲載数トラッキング系のデータ（媒体別・職種別の求人量推移）
- 各社IR資料・決算説明資料（**市場規模と単価構造を推定できる最良の一次資料**。売上÷決定数で実勢単価が逆算できる）
- 業界紙・専門メディア

**規律：** ベンダー調査は必ず「発行主体が何を売っているか」をメタデータに書く。
自社手法に有利な設問設計・母集団選択が入っている前提で読む。数値は層4・層5で三角測量する。

### 層3：学術・エビデンス（信頼性◎／日本文脈への外挿注意）

- 選抜手法の予測妥当性：Schmidt & Hunter (1998) と、その大規模な見直しである Sackett et al. (2022, *Journal of Applied Psychology*)。**後者で妥当性の序列が実質的に書き換わっているため、古いメタ分析だけを引く論者と差がつく論点**。
- 構造化面接、ワークサンプル、認知能力テストの妥当性論争
- RJP（現実的職務予告）と早期離職の関係
- P-O fit / P-J fit と定着・パフォーマンス
- リファラル採用の効果に関する実証研究
- 採用におけるシグナリング理論、サーチ理論
- 日本語圏：日本労務学会、経営行動科学学会、産業・組織心理学会、Works Review、日本労働研究雑誌

**注意点：** 妥当性研究の大半は米国データ。日本の新卒一括採用・長期雇用・職務の曖昧さという条件下で
そのまま成立するとは限らない。**「英語圏の知見 × 日本の制度条件」の突き合わせ自体が、教科書の独自価値になる。**

### 層4：実務一次情報（**最大の差別化源**）

| 情報源 | 取れる情報 | 接触方法 |
|---|---|---|
| 事業会社の人事・採用責任者 | 実運用の歩留まり、やめた手法とその理由 | インタビュー |
| エージェントのRA/CA | 決まる案件・決まらない案件の境界、企業側の見えない事情 | インタビュー |
| 媒体・スカウト媒体の営業 | 料金表、値引き余地、成功事例の実数 | **商談を受ける** |
| RPO / 採用コンサル | 複数社横断の相場観 | インタビュー |
| ヘッドハンター | エグゼクティブ層の力学 | インタビュー |
| 求職者本人 | 手法の受け手側の体験（スカウト文面の刺さり方など） | インタビュー |
| 採用ピッチ資料 | 各社の訴求設計の実物 | 公開資料の収集 |
| 求人票・スカウト文面 | 実物のコピー・条件提示の実態 | 収集・アーカイブ |

**「ベンダーの商談を実際に受ける」は極めて費用対効果が高い。**
料金表・提案ロジック・競合他社への当て方・実績データが1時間で手に入り、しかも無料である。
主要ベンダー20社に対して計画的に実施する。

### 層5：自身の実測データ（**代替不可能な資産**）

自社・支援先の採用データを、**手法別に比較可能な形で**蓄積する。
これがないと「効果」を語れず、他の誰とも差がつかない。

**標準指標の定義を先に固める**（定義が揺れると比較不能になる）：
```
接触数 → 応募/返信数 → 書類通過数 → 一次通過数 → 最終通過数 → 内定数 → 承諾数 → 入社数 → 6ヶ月在籍 → 12ヶ月在籍
＋ 各段階の所要日数
＋ 手法別コスト（媒体費・紹介手数料・人件費工数を含む完全原価）
```

## 4. フェーズ計画

| Phase | 期間目安 | 目的 | 完了条件 |
|---|---|---|---|
| **P0 骨格設計** | 1週 | 分類軸・カードスキーマ・DB確定 | 40〜60枚の空カードがDBに存在する |
| **P1 地図作成** | 2〜4週 | 層1（統計・法制度）を幅優先で制圧 | 市場全体像／法制度対応表／手法シェアの基礎数値が揃う |
| **P2 一次埋め** | 4〜8週 | 層2・3で全カードを7〜8割埋める | 全カードの【機序】【歴史】【市場】が埋まる |
| **P3 一次情報収集** | 継続（3〜6ヶ月） | 層4でインタビュー・商談を実行 | 実務者20〜30名／ベンダー商談20社／【効果】【適合】が埋まる |
| **P4 統合・整合** | 2〜4週 | 矛盾の解消、適合マトリクスの構築、学術との接続 | 軸D×軸E×手法のマトリクスが埋まり、矛盾に説明がついている |
| **P5 公開＝再収集** | 継続 | 書いて出し、訂正と裏情報を引き出す | 当事者からの反応で内容が更新されている |

**P1〜P2 は幅優先で、深追いしない。** 深さは P3 で一次情報から取りに行く。
ここを逆にすると、Web記事の再構成に何ヶ月も溶かすことになる。

## 5. 一次情報の取り方（P3の設計）

### 5-1. インタビュー対象の配分（計20〜30名）

- 事業会社人事：8〜10名（大企業／中小／スタートアップ、都市／地方をばらす）
- エージェント（RA・CA）：5〜6名（大手／特化型／地場をばらす）
- 媒体・スカウト媒体の営業：層4の商談で代替
- RPO・採用コンサル：3〜4名
- ヘッドハンター：2名
- 求職者：5名以上（新卒／中途／現業をばらす）

**選定原則：成功例の主役ではなく、多数の案件を横断して見ている人を優先する。**
1社の成功譚より、100社を見たエージェントの「決まらないパターン」のほうが情報量が多い。

### 5-2. 質問設計（**聞き方が情報の質を決める**）

効かない質問：「御社ではどんな採用手法が有効でしたか？」
→ 成功バイアス・後知恵バイアス・きれいごとしか返ってこない。

効く質問の型：
1. **やめた理由**「過去に導入してやめた手法は？なぜやめた？」
2. **例外**「その手法がうまくいかなかったのはどういう案件？」
3. **相場**「その手法の書類通過率、体感で何%くらい？いい時と悪い時のレンジは？」
4. **配分**「採用予算を今100として、次に10増えたらどこに足す？逆に10削るならどこ？」
5. **境界**「その手法が使えなくなるのは、どういう条件になった時？」
6. **実物**「直近で成功したスカウト文面／求人票を見せてもらえますか？」
7. **裏側**「ベンダーの提案で、実態と違うと感じる点は？」

**記録規律：** 発言は要約せず一次記録として残す。要約は解釈が混ざり、後から別の仮説で読み直せなくなる。

### 5-3. ベンダー商談（計20社）

事前に共通の質問リストを用意し、全社に同じことを聞く（**横比較可能性の確保**）。
- 料金体系の全パターンと、その根拠
- 最低利用期間・解約条件
- 実績値（掲載企業の平均応募数・決定率）とその母集団定義
- 競合手法に対する反論ロジック（← ここに各手法の弱点が最も率直に出る）
- 値引き条件（何を約束すると何%動くか）

### 5-4. 実物アーカイブ

求人票、スカウト文面、採用ピッチ資料、採用サイト、オファーレターの構成、内定者フォロー施策。
**手法の議論は抽象論に流れやすい。実物を数百件持っていることが、記述の解像度を決める。**

## 6. 品質規律

1. **出典メタデータなしの数字は記録しない。** 最低限「出所・発行主体・調査年・n・対象母集団」。
2. **三角測量：** 重要な数値は「ベンダー公表値 × 実務者証言 × 自身の実測」の3点で確認。一致しない場合、**不一致自体を記録する**（不一致の理由がしばしば最も価値のある知見になる）。
3. **反証義務：** 各手法に「効かなかった事例」最低3件。埋まらないカードは未完成扱い。
4. **条件の明記：** 「Xは効果的」は禁止。「軸D=◯、軸E=◯の条件下でXは◯%」の形式でのみ記録する。
5. **一次情報と解釈の分離：** カード内で「観測された事実」と「自分の解釈・仮説」を欄で分ける。
6. **鮮度管理：** 市場・料金・プレイヤーは1〜2年で変わる。カードに最終確認日を持たせ、古いものを検出できるようにする。

## 7. 蓄積基盤（Notion DB — 構築済み）

親ページ「採用手法の教科書｜研究基盤」の下に、以下の5DBを構築済み。

| DB | 役割 | 主要プロパティ |
|---|---|---|
| **DB1 採用手法マスタ** | 1手法1カード。基盤の中心 | 手法ID（MTD連番）／軸A／軸B・C／成熟度／充填ステージ／適合セグメント（軸D）／適合企業条件（軸E）／料金体系／機序4欄／歴史2欄／市場4欄／適合3欄／リスク3欄／エビデンス／自分の解釈・仮説／最終確認日／鮮度 |
| **DB2 出典ライブラリ** | 出所の素性を管理 | 種別／発行主体／利害関係／信頼度A〜D／調査年／対象母集団(n)／母集団の限定条件／三角測量の状況／不一致の内容と考察 |
| **DB3 インタビュー・商談記録** | 一次情報 | 形態／対象者の立場／横断度／取れた論点／抽出した知見／検証が必要な主張／実物の入手 |
| **DB4 実測データ** | 手法別ファネル実数 | 企業条件（軸E）／セグメント（軸D）／ファネル10段階／完全原価／リードタイム／データ確度 |
| **DB5 事例・反証** | 条件依存性の証拠 | 結果／反証事例フラグ／条件（軸D・E）／何が起きたか／機序の説明／この事例が否定する通説／一般化できる範囲 |
| **DB6 企業診断カルテ** | 診断→選定→照合の学習ループ | 診断9変数／binding constraint／制約特定の根拠／手法より先に変えるべきこと／推奨手法／非推奨手法とその理由／想定CPH／実績CPH・CPH乖離%（自動）／診断の的中／外した点 |

**設計上の要点：**

- **リレーションは全てDB1に集約。** 手法カードを開けば、その手法に紐づく出典・証言・実測・反証がすべて並ぶ。教科書の各章はDBビューの書き下しになる。
- **DB1のロールアップ**：反証件数／実測件数／出典件数／証言件数。加えて「反証の充足」式が `あと◯件` を表示し、反証3件の義務が自動で可視化される。
- **KPI相場をDB1に持たせていない。** 条件なしの数値を禁じるため、歩留まりは必ずDB4（企業条件つき）にのみ記録する。DB1から見るときはリレーション越しに条件込みで参照する。
- **DB4は比率を式で自動算出**（応募単価／CPH／書類通過率／内定承諾率／1年定着率）。手入力するのは実数のみで、指標定義の揺れを防ぐ。
- **DB1の「鮮度」式**が最終確認日から18ヶ月超のカードを `要更新` と表示する。
- **DB6が学習ループを閉じる。** 診断（想定CPH）と実測（実績CPH）の乖離が自動算出され、「外した点」がDB1の"効かない条件"を書き換える。詳細は `01_母集団形成の手法選定.md`。
- **「自分の解釈・仮説」欄を独立**させ、観測事実と解釈を混ぜない規律を構造で担保する。

**投入済み**：
- A2 母集団形成 32手法 … **充填ステージ1（機序・適合条件・支払う通貨・売り手の歪み・法的制約まで）**。内容は `02_A2手法カード_一次充填.md` と同一
- A1・A3・A4・A5 の30手法 … 充填ステージ0（空カード）

推奨ビュー（Notion側で作成）：
- 充填ステージ別ボード（次に埋めるカードが一目で分かる）
- 軸D×軸Bのギャラリー（適合マトリクスの空白セル検出用）
- 「反証の充足 ≠ 充足」フィルタ（未完成カードの棚卸し）
- 「鮮度 = 要更新」フィルタ（月次の鮮度アラート）

## 8. 週次運用ルーチン

| 頻度 | やること |
|---|---|
| 週次 | 未完成カードのうち完成度が最も低い3枚を選び、埋めるための情報を1つ取りに行く |
| 週次 | インタビューまたはベンダー商談を最低1件 |
| 週次 | 実物アーカイブ（求人票・スカウト文面等）を10件収集 |
| 月次 | 適合マトリクスの空白セルを棚卸しし、次月の収集対象を決める |
| 月次 | 三角測量で不一致が出た数値を洗い出し、原因を追う |
| 四半期 | 公開アウトプットを1本出し、反応から訂正・追加情報を回収する |

**進捗指標：** 「読んだ量」ではなく **「適合マトリクスの充填率」** で管理する。

## 9. 到達度の検証方法

定期的に以下のセルフテストを行う。答えられない箇所が、次の収集対象になる。

1. ランダムに企業条件を1つ設定し、手法選択・予算配分・想定KPI・根拠を10分で書けるか
2. 任意の手法について、料金体系・実勢相場・値引き余地を数字で言えるか
3. 任意の手法について、「効かない条件」を3つ、機序つきで説明できるか
4. 「この手法はなぜ2010年代に登場したのか」を、労働市場・技術・法制度の変化から説明できるか
5. 世間で常識とされる採用のセオリーを1つ選び、その反証データを提示できるか
6. 現場の実務者に説明したとき、「それは知らなかった」と言われる情報が含まれているか（← **最も実効的なテスト**）

## 10. リスクと対処

| リスク | 兆候 | 対処 |
|---|---|---|
| Web記事の要約で終わる | カードの【機序】【市場】ばかり埋まり【効果】【適合】が空 | P2に期限を切り、強制的にP3へ移行する |
| ベンダーバイアスの内面化 | 特定手法を無条件に推している自分に気づく | 反証義務と三角測量を機械的に回す |
| A2（母集団形成）偏重 | A3〜A5のカードが薄い | カード数を軸Aごとに割当てて管理する |
| 米国研究の無批判な輸入 | 妥当性係数をそのまま日本の文脈で語っている | 制度条件の差分を必ず併記する |
| 情報の陳腐化 | 最終確認日が2年以上前のカードが増える | 鮮度アラートを月次で確認 |
| 網羅を狙って何も出せない | 何ヶ月もアウトプットがない | P5を待たず、四半期ごとに未完成のまま公開する |
